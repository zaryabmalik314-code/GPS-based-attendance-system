# SmartAttend Backend

FastAPI backend for GPS geofencing + face recognition faculty attendance.

## Structure
```
app/
  main.py         - routes
  models.py       - SQLAlchemy models (Faculty, AttendanceRecord)
  schemas.py      - Pydantic request/response models
  database.py     - DB session (SQLite local / Postgres on Railway)
  geofence.py     - polygon ray-casting + GPS accuracy handling
  face_verify.py  - cosine similarity face matching
requirements.txt
Procfile          - for Railway
```

## Local run
```
pip install -r requirements.txt --break-system-packages
uvicorn app.main:app --reload
```
Visit http://localhost:8000/docs for interactive API docs (auto-generated by FastAPI).

## Before deploying
1. **Fill in `CAMPUS_BOUNDARY`** in `app/geofence.py` with your real 16-point polygon from SCEMS.
2. **Tune `FACE_MATCH_THRESHOLD`** in `app/face_verify.py` once you have real face-api.js embeddings — 0.6 is a starting guess, not gospel.
3. **Lock down CORS** in `main.py` (`allow_origins=["*"]` → your actual frontend domain).
4. On Railway: add a Postgres plugin, it auto-injects `DATABASE_URL`. No code changes needed — `database.py` already handles it.

## Frontend integration notes
- Send **3-5 GPS readings** taken over ~5-10 seconds to `/api/attendance/check-in`, not just one. Backend picks the most accurate.
- Send the face-api.js descriptor (128-length float array) as `face_embedding`.
- Optionally send `wifi_ssid` as a secondary "on campus" signal (frontend would need to read this via a native wrapper/TWA, not plain browser JS — browsers can't read WiFi SSID directly for privacy reasons. Worth checking if your PWA-to-APK wrapper exposes it.)

## Endpoints
- `POST /api/faculty/enroll` — enroll faculty with name/email/face embedding
- `GET /api/faculty` — list enrolled faculty
- `POST /api/attendance/check-in` — the main check-in flow (GPS + face verify)
- `GET /api/attendance?faculty_id=` — attendance history
